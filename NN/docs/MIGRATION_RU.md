# Обновление NN 0.3.0 → 0.4.0

1. Сохраните собственные изменения исходников NN, если делали их после 0.3.0.
2. Распакуйте ZIP в родительскую PGR_Net с заменой файлов. В корне ZIP только NN/.
3. Из NN запустите python test_all.py и python build_and_test.py.
4. Проверьте Storage tests: 27; failures: 0, model_roundtrip_exact: true
   и storage_cli_tests: OK. Модель находится в новой nn_results_.../training_demo.

Новая версия включает все прежние этапы внутри NN. Никакой старый внешний
каталог не нужен как зависимость. Соседний структурированный BD остаётся:
BD/projects, catalog, splits, observations, datasets, repairs, tools,
reports, manifests, docs и bd.py. Подробнее — BD_STRUCTURE_RU.md.

Прежние nn_results_... являются вашей историей и не удаляются. Программа
не массово удаляет файлы и не пытается отличить личные дополнения от исходников.
PGR_make/PGR_Make, BD и отдельный Lean-проект с Mathlib не удалять.
Ранние автономные PGR_* комплекты можно убрать вручную после сохранения
собственных данных и проверки новой NN; их код уже собран в модулях NN.

Файлов .pgrnn в 0.3.0 ещё не было, поэтому миграции старых весов нет. Старые
run.json/history.csv — отчёты и не содержат все параметры сети. Нельзя
восстановить прошлые веса из одного final_loss. Повтор опыта с тем же seed
и настройками на том же бинарнике создаёт собственные веса заново.
