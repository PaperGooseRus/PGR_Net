# Математика SGD и учебного цикла 0.3.0

## Что добавлено к 0.2.0

Для набора батча B сначала используется уже проверенный средний градиент:

    g = (1/|B|) sum_(x,y in B) grad_theta L(theta;x,y)
    theta_new = theta - eta*g, eta>0

Обновляются E, W1, b1, W2, b2. Размер последнего неполного батча берётся
фактический, не заданный batch_size. Регуляризация, momentum, Adam, clipping
и адаптация шага отсутствуют; базовые формулы loss/backward не изменены.

sgd_step возвращает новую Network. Исходная сеть не изменяется и при ошибке.
Сначала проверяются размеры и конечность градиента и eta, затем конечность
изменений и новых параметров. Непредставимая арифметика даёт исключение,
а не тихую замену значений. Это не доказательство корректности оптимизатора
для любых весов, датасетов и шагов.

## Инициализация и случайность

Используется полностью заданный unsigned SplitMix64 и преобразование старших
53 бит в uniform[0,1). E инициализируется uniform[-0.5,0.5), W1/W2 — Xavier
uniform с границей sqrt(6/(fan_in+fan_out)), b1=0.1, b2=0. Это начальная
конфигурация учебного эксперимента, не доказанно оптимальная архитектура.
Генератор не криптографический и не предназначен для безопасности.

Инициализация принимает свой seed. TrainOptions.shuffle_seed влияет только
на порядок примеров и не переинициализирует переданную Network. Демо задаёт
им один seed для простого воспроизведения. Каждая эпоха начинается с исходного
порядка индексов и перемешивается Fisher–Yates с rejection sampling для индексов.

При одинаковом бинарнике/платформе/seed/данных/опциях опыт повторяется точно.
Unsigned-битовый поток определён одинаково, но sqrt/exp и оптимизация double
могут отличаться между платформами. Нельзя обещать побитно одинаковое обучение
между компиляторами. fast-math не включён.

## Учебная задача

V=5, d=4, C=2, S=2, H=8, K=2. Токен 0 зарезервирован под unknown, в учебных
примерах используются индексы 1..4. Восемь последовательностей:

- class 0: [1], [2], [1,2], [2,1,1];
- class 1: [3], [4], [3,4], [4,3,3].

Контекст у всех compiler=0, stage=0. Текст, реальные компиляторные сообщения,
BD, патчи и целевая разметка на вход признаков не подаются. Это намеренно
маленькая задача для проверки обновления весов, а не модель «понимания сборки».

80 эпох, batch=4, eta=0.15, seed=20261028 дают 160 шагов. История содержит
метрики полного того же учебного набора после эпохи и epoch=0 до обучения.
Логиты выбираются argmax с меньшим индексом при равенстве. Независимой
validation/test-выборки здесь нет; метрики так и названы training_*.

## Ограничения

Один вызывающий поток, без фонового обучения. Лимиты: batch<=256,
examples<=100000, epochs<=10000, updates<=100000. Это защита от случайного
слишком большого запуска, не квота ресурсов ОС. Полные градиенты таблиц
и новые Network копируются; производственная оптимизация и измерения памяти
будут нужны позднее. Для текущих восьми примеров объёмы малы.

Конечные разности в 0.2.0 проверяют производные в выбранных точках; новые
тесты проверяют SGD и поведение цикла. В Lean их формализация не выполнена.
Ни SGD сам по себе, ни успешное запоминание восьми примеров не гарантируют
сходимость произвольной сети или качество на неизвестных проектах.
