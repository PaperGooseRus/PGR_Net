# Передача разработки в новый чат

## Цель

Разработать собственную специализированную сеть для локального Windows-приложения PGR_Make. Только диагностика/сопровождение сборки C/C++: Desktop, позднее STM32 и другие toolchain. Собственные обучение, веса и движок; без обязательных облаков, веб-сервера и готовых чужих моделей. Оригинальное ядро и Pack Manager сохраняются. Этот архив самостоятелен, не является изменением PGR_Make.

## Уже сделано

- Определена кандидатная модель с представлениями токенов, средним вектором, одним скрытым слоем и softmax. См. MATHEMATICAL_MODEL_RU.md.
- Подготовлен Lean 4-файл; пользователь подтвердил успешную проверку предыдущего экземпляра. Границы доказательств записаны отдельно, версии окружения надо сохранить.
- Получены реальные сообщения MinGW 16.2.0 на искусственных программах; исправлены метаданные ОС и временные пути.
- Сделан классификатор правил v1 и его Windows-исправление cp1252.
- На challenge-наборе Windows v1 дал 22/24, две корректные программы собрались. Два отказа: заголовок без расширения и пропущенная скобка.
- В текущем комплекте v2 закрывает оба случая, добавлен контекст include и граничные тесты. v1 сохранён неизменным. Сравнение на всех включённых Windows-данных: 48/48 для v2 против 46/48 для v1, два успешных контроля. Это разработческая, не независимая оценка.
- Подготовлены 54 учебных проекта и 12 групп тестов. Локальный Linux GCC 13.3 дал 48/48 для v2 и 6 успешных контролей; новая версия ещё не запускалась на Windows.

## Чего НЕ сделано

Нейросеть на C++/Python, обучение, веса, подтверждённое качество на независимых проектах, интеграция Qt/PGR_Make, свободный чат, агентные действия, доступ нейросети к WinAPI, ARM-прогоны, GPU. Импорт правил в GUI не является реализацией собственной сети.

## Следующая ограниченная задача

Создать самостоятельный минимальный CPU-прототип вычислений и обучения сети согласно зафиксированным формулам, без интеграции в PGR_Make. В качестве архитектурного направления предпочтителен C++17 с простым CMake и тестами; конкретная структура согласуется в том чате. Не расширять бесконечно правила и не менять математическую модель молча.

Последовательность до пяти этапов:

1. README, точные размеры и версии формата/словаря; CPU-прямой проход с заданными весами. Проверить на небольшом вручную вычисляемом примере.
2. Производные нужных операций и кросс-энтропия. Сравнение аналитических градиентов с конечными разностями вдали от нуля ReLU. Тесты не считать формальным доказательством.
3. Учебное обучение с фиксируемым seed и сохранение/загрузка весов с проверкой размерностей, размеров и версии. Приложенные данные пригодны только для smoke/demo.
4. Сбор и независимое разделение реальных проектов, обучение и сравнение с замороженными правилами, пороги/отказ и калибровка.
5. Измерения CPU/RAM/задержки в Windows и оформление решения о последующей интеграции. Пороговые значения ресурсов не выдумывать заранее как доказанные.

Первый реализуемый результат должен быть самым простым: прямой проход и понятная проверка чисел. Пользователь хочет понимать код: русские комментарии, небольшие модули, простой стек. Python в этом архиве — инструменты подготовки и тестирования, не обязательный runtime будущей модели.

## Правила продолжения

- Не выдавать созданные искусственные примеры за независимые реальные проекты и не выдумывать дополнительные собранные журналы.
- Не использовать test для словаря, выбора архитектуры или настройки порога.
- Уважать разницу симптома и причины. Имена файлов/целей/MCU подтверждаются детерминированно.
- Не трактовать softmax=0.95 как доказанную вероятность или достаточное разрешение на действие.
- Файлы проекта не изменять без конкретного просмотренного предложения и разрешения; агентный режим проектируется отдельно.
- Не связывать MCU и host Windows, и не считать v1/v2 нейросетью.
- Для изменения математики фиксировать формулы и предположения; обсуждение и новые Lean-доказательства пользователь планирует вести в исходном чате.
