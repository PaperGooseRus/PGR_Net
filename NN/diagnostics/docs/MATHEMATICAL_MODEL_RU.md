# Зафиксированная кандидатная математическая модель

## Назначение и статус

PGR Neural — собственная локальная специализированная подсистема для диагностики сборки C/C++ Desktop и embedded-проектов. Первая задача — классификация симптомов английских сообщений GCC/MinGW. Cortex-M/STM32, другие компиляторы и языковой агент — последующие расширения, не текущая реализованная функциональность.

Сеть, веса, обучение и интерфейс естественного языка отсутствуют. Правила в архиве — сравниваемый ориентир, а не нейросеть. Модель ниже кандидатная: она ещё не доказала практической эффективности. Не используются готовые чужие модели и веса; будущий движок предполагается на C++ с обязательным CPU-режимом. Работа сборки PGR Core должна оставаться доступной без сети и интернета.

## Вход и выход

Вход — один диагностический блок, известный инструмент и стадия. Должна различаться ОС хоста, target triple компилятора, архитектура процессора и конкретный MCU; одна характеристика не доказывает другую. Сеть не должна выводить тип STM32 из одного только Cortex-M4.

Сейчас семь известных классов: header_missing, syntax_error, undeclared_identifier, type_mismatch, undefined_reference, multiple_definition, unknown_option. out_of_scope — метка проверки границы области; unknown — решение отказаться от ответа. Не следует автоматически делать их восьмым обучаемым классом. Формальная модель параметризована K>=1, поэтому применима как к семи, так и к другому согласованному количеству классов.

Нужен отдельный внешний словарь категорий и версия токенизации. Неизвестным токенам соответствует <unk>. Пустое сообщение отклоняется или заменяется специальным непустым вводом — решение фиксируется до реализации. Среднее представление теряет порядок слов; это известное ограничение, а не формально доказанная достаточность архитектуры.

## Прямой проход

V — размер словаря, d — размер представления токена, H — число скрытых нейронов; q — количество контекстных признаков. Начальные значения для эксперимента: V<=2000, d=32, H=32. Это гиперпараметры, не обязательные оптимальные величины. Длина сообщения предварительно ограничивается, например 128 токенами, с сохранением исходного блока для диагностики.

Матрица представлений E имеет размер V x d. Для непустой последовательности токенов (t_1,...,t_n):

    m = (1/n) * sum_i E[t_i],   n>0
    x = concat(m, compiler_one_hot, stage_one_hot)
    h = ReLU(W1*x + b1)
    z = W2*h + b2
    p_k = exp(z_k - a) / sum_j exp(z_j - a)
    a = max_j z_j

Размерности: x — d+q; W1 — H x (d+q); b1 — H; W2 — K x H; b2 — K. Вещественные формулы softmax с вычитанием общего a и без него эквивалентны; эквивалентность не включена в приложенные Lean-доказательства.

## Обучение и оценка

Категориальная кросс-энтропия:

    L_data = -(1/N) * sum_i log(p_i[y_i])
    L = L_data + lambda * ||theta||_2^2

Регуляризация, её параметры, оптимизатор и число эпох выбираются по проверочным данным. Полная общая библиотека autograd необязательна для первой сети; достаточно проверенной специализированной реализации нужных производных.

Для одинакового логита softmax и кросс-энтропии градиент по логитам p-y; для ReLU в нуле требуется согласованная конвенция субградиента. Математическое обоснование и тесты градиентов — отдельная следующая работа; приложенный Lean-файл их НЕ доказывает.

Словарь, статистики нормализации и веса строятся только по train. Разделение должно учитывать независимые проекты и близкие шаблоны. Данные в архиве регрессионные, не train/validation/test для объективной метрики. Нельзя обучить и честно оценить сеть случайным перемешиванием этих строк; одни и те же программы под Linux и Windows также связаны.

Требуемые будущие метрики: precision/recall и F1 по классам, macro-F1, матрица ошибок, доля отказов, качество среди принятых ответов, ложные принятия неизвестных, задержка и память. Пороги выбираются на validation, не test. Softmax сам по себе не калиброванная вероятность и не надёжный детектор незнакомого ввода. Калибровка и отказ проверяются отдельно.

## Что подтверждено Lean

Пользователь сообщил успешный полный запуск ранее предоставленного файла в Lean 4 + Mathlib после исправления двух доказательств. В архив скопирована последняя доступная версия этого исходника, без изменения формул. В текущем окружении Lean не запускался; точные версии Lean/Mathlib того успешного пользовательского запуска не сохранены. Следует получить lean-toolchain и lake-manifest.json пользователя перед утверждением воспроизводимости.

В файле заданы размерности через типы и доказаны отдельные свойства: положительность длины непустого сообщения, ReLU, скрытого слоя, знаменателя и выходов softmax, сумма softmax=1 над R, пороговый отказ для уже выбранного кандидата и простая булева модель разрешений. Не доказаны argmax, свойства обучения, качество данных, устойчивость на неизвестных запросах, численная реализация float32, C++, WinAPI и реальные разрешения файлов. Это не доказательство правильности всей AI-системы.

## Ограничения ресурсов и действий

Сначала CPU и один рабочий поток для инференса, ограничение длины входа и очереди. Обучение отдельно от обычной сборки, только по явному запуску. GPU, квантование и универсальный диалог не обязательны. Ограничения времени и памяти в числах устанавливаются измерениями на целевых Windows-компьютерах.

Модель предлагает категорию и гипотезу. Детерминированный PGR Core проверяет факты. Действия только через типизированные инструменты: preview/diff, соответствующее разрешение пользователя, повторная проверка состояния перед записью. Успешная компиляция не доказывает функциональную правильность исправления. Нативное API/WinAPI-исполнение, установки, прошивка и сеть не входят в этот комплект и не разрешаются моделью напрямую.
