# PGR Neural — завершающий комплект базовой диагностики

Версия: 2.0.0-baseline. Дата: 28.10.2026.

Это самостоятельный проект рядом с существующими папками. Старые файлы, PGR_Make, Qt, настройки Windows и формальная модель не изменяются. Нейросеть пока не реализована и не обучена. Этот комплект фиксирует проверяемый ориентир для её дальнейшей разработки.

## Быстрый запуск в Windows CMD

Распакуйте папку `PGR_Neural_Baseline_Final`, например в `C:\Project\PGR_Net`. В CMD:

```bat
cd /d C:\Project\PGR_Net\PGR_Neural_Baseline_Final
python test_all.py -v
python evaluate.py
python run_suite.py
```

Первые две команды не требуют компилятора. Последняя собирает 54 учебных проекта и требует g++ MinGW в PATH. Проверка: `g++ --version`.

Полный путь к компилятору при необходимости:

```bat
python run_suite.py --compiler "C:\msys64\ucrt64\bin\g++.exe"
```

Результаты каждой команды создаются в отдельной новой папке рядом со скриптами: `evaluation_...` или `final_results_...`. Они содержат `report.txt`, `summary.json`, `predictions.jsonl`. Для сборок добавляются `results.jsonl`, `environment.json` и `logs`. Путь к папке выводится в конце.

Существующая папка не перезаписывается. При повторном запуске в ту же секунду подождите секунду либо укажите новое имя:

```bat
python run_suite.py --output final_windows_01
```

Для ранее собранного файла, без повторной сборки:

```bat
python evaluate.py "C:\Project\PGR_Net\some_results\results.jsonl" --output review_01
```

Родитель выходной папки должен существовать. Вход: форматы предыдущих diagnostics.jsonl и results.jsonl с id, label, diagnostic и stage; статусы сбора необязательны. Для точного распознавания отсутствующих заголовков нужен raw_stderr с соответствующей строкой #include из GCC. Если контекста нет, v2 может возвращать unknown даже для .h — это более осторожная политика.

## Что изменилось

- Для заголовков проверяется контекст #include, а не расширение имени. Поддерживаются имена без расширения и с пробелами, если GCC вывел соответствующую исходную строку.
- Добавлены варианты пропущенных скобок/разделителей, конца файла, явных ошибок ссылок и сужающих преобразований.
- Учтён диагностический суффикс GCC 16 `[-Wtemplate-body]`.
- Предупреждения, note, неоднозначные и неподдерживаемые сообщения дают отказ unknown.
- Ограничена длина диагностической строки и контекста include.
- Сохранена исходная версия правил v1 для сравнения и исправление вывода при cp1252.
- Записи label, expected_marker и notes не используются как признаки классификатора.

## Какие проверки включены

1. 50 сохранённых Windows-результатов пользователя: 48 ошибочных сборок и 2 успешные; версии и происхождение сохранены в данных. Это знакомые разработческие данные.
2. 54 воспроизводимых C++17-проекта: 48 намеренно ошибочных и 6 корректных. Их части повторяют прежние сценарии и не считаются независимыми проектами.
3. 12 групп автоматических тестов с положительными, отрицательными и пограничными случаями, проверкой кодировки, неверного JSON, отсутствующего компилятора и защиты отчётов от перезаписи.

Сборки запускаются по одной во временных каталогах. Исполняемые файлы не запускаются. Используются только встроенные примеры, исходники личных проектов не читаются. Временные результаты удаляются. Тайм-аут --timeout относится к процессу запуска g++, а не гарантированно ко всему дереву процессов Windows. Сам Python-скрипт, запущенный пользователем, выполняет сборки: это не реализованный агентный режим нейросети.

Коды завершения: 0 — операция закончена, даже если есть несовпадения классификации; 1 у run_suite.py — проблемы сбора; 2 — ошибка подготовки/ввода/записи. Неожиданное сообщение новой версии GCC сохраняется и требует просмотра, но не означает, что нужно бесконечно расширять правила.

## Ограничения и критерий завершения этапа

Все возможные ошибки сборки охватить невозможно. Семь категорий — фиксированная задача текущего этапа; остальные случаи отклоняются. Ошибки CMake, MSVC, ARM linker, разрешений, диска, нехватки памяти и другие представлены в тестах отказа как синтетические строки, а не реальные прогоны этих инструментов. Новая версия не заявляет их диагностику или исправление. Даже отказ unknown не гарантирован на любой ранее невиданной строке.

Этот этап можно завершить после успешного запуска тестов, записи отчётов и просмотра проблем сбора/регрессий на целевой Windows. Число совпадений на разработческих примерах не является метрикой обобщения. Дополнительные правила не являются обязательным условием перехода к нейросети. Её самостоятельная оценка позднее потребует отдельно отложенных независимых проектов.

## Передача в другой чат

Загрузите этот архив в новый чат и укажите начать с `docs/HANDOFF_RU.md`. Там зафиксированы математика, требования, текущее состояние и следующая ограниченная задача. Детали модели и новые доказательства можно продолжать обсуждать в исходном чате. Для математики см. `docs/MATHEMATICAL_MODEL_RU.md`; для формальной проверки — `formal/PGR_Neural_Verification.lean`.

Новый комплект проверен локально на Linux GCC 13.3 и сохранённых логах Windows MinGW 16.2. Нативный запуск новой версии на Windows ещё предстоит. Все файлы отчётов имеют кодировку UTF-8. Перед передачей отчётов проверьте остаточные пути к инструментам: маскировка временных файлов не является полной анонимизацией.
