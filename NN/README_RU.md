# PGR Neural — NN 0.4.0: собственный файл весов

Полный самостоятельный комплект NN рядом с существующей BD. Версия сохраняет
forward, градиенты, SGD, прежнюю диагностику и адаптер BD v1/v2. Добавлен модуль
storage: сохранение и загрузка Shape и всех параметров в формате `.pgrnn` v1.

Учебный SGD теперь создаёт настоящий файл весов. Отдельный процесс загружает
его и проверяет совпадение логитов и вероятностей. Это пока задача на восьми
учебных примерах индексов, не обученная на BD система диагностики.

## Установка и запуск в Windows CMD

Распакуйте архив в PGR_Net с заменой файлов внутри NN. В архиве только NN/;
BD, PGR_Make и старые nn_results_... не требуется удалять. Если меняли исходники
NN самостоятельно, сохраните свою копию перед заменой.

```bat
cd /d C:\Users\d.gusev\Documents\Project\PGR_Net\NN
python test_all.py
python build_and_test.py
```

При необходимости `python verify_package.py` сверяет SHA-256 файлов поставки.
Личные логи и результаты опытов в эту проверку не входят.

Нужны Python >=3.10 и g++ с C++17 (MinGW на Windows) в PATH. CMake, интернет
и сторонние Python-пакеты для этого способа не нужны. При необходимости:

```bat
python build_and_test.py --compiler "C:\msys64\ucrt64\bin\g++.exe"
```

test_all.py проверяет 16 прежних Python-тестов. build_and_test.py компилирует
65 C++-тестов (15 forward + 13 gradients + 10 training + 27 storage), четыре
демонстрации и автоматически запускает ещё 11 Python-тестов готовых программ.
Все журналы записываются в UTF-8. Каждая папка результата должна быть новой.

Ожидаемые основные строки:

```text
Tests: 15; failures: 0
Gradient tests: 13; failures: 0
Training tests: 10; failures: 0
Storage tests: 27; failures: 0
final_training_accuracy: 1
updates: 160
model_saved: model.pgrnn
model_roundtrip_exact: true
storage_cli_tests: OK
```

Как и в 0.3.0, default-опыт даёт loss примерно 0.7696972732 → 0.0045391035.
Это training-метрики восьми примеров, не независимая оценка. Последние цифры
double могут различаться между платформами.

## Где модель и как загрузить её отдельно

Новая nn_results_YYYYMMDD_HHMMSS содержит восемь бинарников, логи, summary.json
и каталог training_demo:

| Файл | Ответственность |
|---|---|
| model.pgrnn | Размеры сети и биты всех E/W1/b1/W2/b2; не CSV и не отчёт |
| history.csv | Метрики epoch=0 и 80 эпох обучения |
| run.json | Seed, настройки опыта, метрики и контрольный вход/выход |

Подставьте реальное имя созданной папки:

```bat
nn_results_YYYYMMDD_HHMMSS\pgr_neural_model_demo.exe --input nn_results_YYYYMMDD_HHMMSS\training_demo\model.pgrnn --tokens 1,2 --compiler 0 --stage 0
```

Это новый процесс: он загружает параметры и печатает JSON с логитами и
вероятностями, обучение не запускается. Параметры --tokens/--compiler/--stage
обязательны; передаются уже числовые индексы. Для default-опыта вероятность
первого учебного класса на этом входе примерно 0.9969625286.

`--copy-to NEW_FILE` сохраняет проверенную модель под новым именем. Существующий
файл не заменяется даже при конкурирующих сохранениях. Родитель должен существовать.
Файловый API и обе CLI поддерживают кириллицу/пробелы в путях; ставьте кавычки.
MinGW DLL должны быть доступны в PATH. Сборщик добавляет каталог выбранного g++
к PATH своих дочерних процессов; при ручном запуске это делает ваше окружение.

## Повторить обучение без пересборки

```bat
nn_results_YYYYMMDD_HHMMSS\pgr_neural_training_demo.exe --seed 20261028 --epochs 80 --batch-size 4 --learning-rate 0.15 --output experiment_01
```

Каталог experiment_01 должен быть новым, его родитель существовать. Без --output
опыт вычисляется только в памяти. Параметры --help печатают подсказку обеих CLI.
При одинаковом seed и настройках в том же бинарнике model.pgrnn, CSV и JSON
совпадают побайтно. Вычислительное совпадение Windows и Linux побитно не обещается.

.pgrnn хранит модель для вычислений, а не полный checkpoint обучения. Состояние
PRNG перемешивания, позиция батча и текущая эпоха не сериализуются. run.json
содержит настройки, но одного seed недостаточно для точного продолжения с
места остановки. Модель не содержит строкового словаря, label map и названий
контекстов: смысл числовых индексов пока задаёт вызывающий код.

## Модули

| Каталог | Ответственность |
|---|---|
| math/ | Матрицы, affine, ReLU, softmax |
| model/ | Shape, Parameters, неизменяемая Network и forward |
| training/ | Loss, backward, инициализация из seed, SGD, цикл |
| storage/ | .pgrnn, контроль размеров/CRC/чисел, load и сохранение нового файла |
| demo/, tests/ | Четыре CLI-примера, проверки и независимый бинарный эталон |
| diagnostics/ | Прежние диагностические правила и регрессионные проекты |
| data_tools/ | Аудит BD v1/v2 без обучения и изменения данных |
| formal/ | Прежние Lean-исходники с прежними границами доказательств |
| docs/ | Формат файла, архитектура, математика, миграция и результаты проверки |

Подробная спецификация: docs/MODEL_FORMAT_RU.md. C++ API:
`storage/include/pgr/neural/model_io.hpp`. Все новые исходники снабжены русскими
комментариями. Версия формата 1 независима от версии программы 0.4.0.

При установленном CMake >=3.20/Ninja доступен второй путь:

```bat
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

CTest запускает C++-проверки; 11 CLI-проверок отдельно:
`python tests\test_model_cli.py --bin-dir build\demo` для single-config Ninja.
Сборка через CMake здесь не запускалась. Реально проверен g++ на Linux.
Пользователь подтвердил 0.3.0 на Windows; новая 0.4.0 ждёт Windows-прогона.

## BD и границы этого этапа

`python data_tools\inspect_bd.py --bd "..\BD"` — прежний аудит структуры.
Новая версия не изменяет BD и не выбирает скрыто два/семь/117 классов для корпуса.
Контракт BD, подготовка словаря по train и обучение диагностике — следующий
отдельный этап. runner_error прежнего сборщика BD остаётся отдельной задачей.

Формат проверяет целостность и структурную пригодность, а не качество весов.
CRC-32 не является цифровой подписью. Конечные веса могут приводить к переполнению
на некоторых входах: существующий forward явно отклоняет такие вычисления.
Lean не доказывает C++ сериализатор, double, backward или SGD. Qt/PGR_Make,
агентные действия и управление системой на этом этапе не добавлялись.
