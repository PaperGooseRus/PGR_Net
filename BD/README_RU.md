# BD v2 — структурированный корпус PGR Neural

BD — твой генератор, проекты и данные. NN рядом — код сети и её тесты.
В этой поставке уже находятся все 7424 проекта исходного архива, исходная
разметка, наблюдения и подготовленные выборки. Повторная генерация не нужна.
Значения и содержимое данных не изменены, изменены размещение и пути скриптов.

## Одна точка запуска

Открой CMD в BD и выполни:

```bat
python bd.py info
python bd.py check
python bd.py test
python bd.py audit
```

Нужен Python >=3.10. Для этих команд компиляторы и интернет не требуются.
check проверяет SHA-256 выпущенного снимка; test — четыре группы проверок
структуры и генерацию небольшого корпуса во временной папке; audit — каталог,
пары, разбиения и наличие файлов. Все команды могут запускаться через bd.py;
искать скрипты по подпапкам не нужно.

## Каждый каталог имеет одну роль

| Каталог | Назначение |
|---|---|
| tools/ | Исполняемый код генератора и обработки; обычно напрямую не открывать |
| projects/ | Только исходники 7424 учебных проектов и их CMakeLists.txt |
| catalog/ | Общий каталог проектов, CSV, таксономия и сводка генерации |
| splits/ | Только принадлежность проектов к train/val/test |
| repairs/ | Только парные патчи неисправный→исправный |
| observations/gcc/ | Исходные наблюдения GCC: observations.jsonl |
| observations/clang/ | Исходные наблюдения Clang: observations.jsonl |
| datasets/gcc/ | Подготовленные train.jsonl, val.jsonl, test.jsonl для GCC |
| datasets/clang/ | Те же подготовленные выборки для Clang |
| reports/collection/ | Сводки стандартных сборочных прогонов |
| reports/validation/ | Актуальный audit_report.json о структуре и наблюдениях |
| reports/history/ | Исторические сводки из исходного архива; не текущие гарантии |
| manifests/ | Хеши текущей поставки и таблица переноса исходных файлов |
| docs/ | Описание структуры и процессов; source_v1 — историческая документация |

В корне только bd.py, layout.json и README_RU.md. layout.json сообщает
инструментам номер раскладки 2; содержимое записей соответствует прежнему
контракту Synthetic Corpus v1. Все относительные project paths сохранились,
потому что projects/ осталась в корне.

## Как выполнять дальнейшие операции

Справка по каждой операции: `python bd.py <команда> --help`.

### Новый корпус в отдельной папке

```bat
python bd.py generate --out "..\BD_next" --copies 32 --seed 20261028
python bd.py repairs --root "..\BD_next"
python bd.py audit --root "..\BD_next"
```

Генератор не перезаписывает существующую папку. Новый каталог содержит данные
в структуре v2. Код инструментов остаётся в исходном BD/tools: --root позволяет
обслуживать разные версии данных одним набором скриптов.

### Собрать и проверить проекты

Требуются gcc/g++, CMake и, при наличии, Ninja. Для Clang — clang/clang++.
Команда collect компилирует и ЗАПУСКАЕТ учебные программы, как твой verify.py;
это не безопасная песочница для произвольных подменённых исходников.

Пробный прогон по одной паре на категорию в отдельную папку:

```bat
python bd.py collect --compiler gcc --sample-per-family 1 --strict --output-dir observations\gcc\sample_01
```

Этот явный отдельный каталог содержит observations.jsonl и report.json и не
заменяет основной набор. Полная замена основных GCC-наблюдений:

```bat
python bd.py collect --compiler gcc --jobs 4 --strict --overwrite
```

Наблюдения будут в observations/gcc/observations.jsonl, сводка — в
reports/collection/gcc_report.json. Без --overwrite существующий файл
наблюдений не заменяется. --strict даёт ненулевой код при несовпадениях.

### Подготовить выборки из основных наблюдений

```bat
python bd.py prepare --compiler gcc --include-sources
```

Команда обновляет datasets/gcc/{train,val,test}.jsonl и исключает наблюдения
с match=false. Для обоих компиляторов: --compiler all. Пары и метки остаются
в catalog/splits/repairs; метки и патчи нельзя подавать в признаки модели.

После изменения наблюдений/выборок старый хеш-манифест исходной поставки
может перестать совпадать — это ожидаемая фиксация изменения данных, а не
поломка структуры. Он не обновляется автоматически с целью скрыть изменения.

## Обнаруженное в исходном архиве

В предоставленных GCC-наблюдениях уже было 28 записей match=false из 7424;
в Clang — 0. В том числе есть runner_error Windows. Они перенесены без
исправления меток или подмены результатов. Исторический validation_summary
из исходника заявлял 0 — поэтому он теперь явно помещён в reports/history.
Текущий audit показывает фактические числа. При необходимости строгой проверки:

```bat
python bd.py audit --strict-observations
```

Для поставленных GCC-наблюдений эта команда намеренно вернёт код 1.
Обычный audit завершится кодом 0 при корректной структуре и выведет отдельное
предупреждение о несовпадениях. Ранее подготовленные выборки могут содержать
примеры из этих прогонов; адаптер NN выводит rows_with_failed_observation.
Переподготовка GCC в временной проверке дала 7396 записей — исходные данные
в архиве при этом не изменялись.

## Связь с NN

Архив содержит небольшое обновление NN/data_tools/inspect_bd.py и описание
BD для уже установленного NN 0.2.0. Математика, градиенты и веса NN не меняются.
После распаковки рядом, из NN:

```bat
python data_tools\inspect_bd.py --bd "..\BD"
```

Поддержка старой структуры Synthetic Corpus v1 также сохранена. Адаптер
ничего не пишет в BD и не обучает модель. Разбиение по парам не означает
независимости шаблонов, runtime_error не означает ошибку сборки — эти
смысловые ограничения исходного корпуса остаются в силе.

Новую раскладку/скрипты проверили на Linux; Windows-прогон этой версии ещё
предстоит. Все тексты UTF-8. Лаунчер задаёт UTF-8 для перенаправленных потоков.

## Этап 3 (BD v2.1): подготовка проверенной обучающей базы

Структура BD v2 сохранена. Дополнительно созданы выборки
`datasets/verified/{gcc,clang}/{train,val,test}.jsonl`, куда включены
только пары, подтверждённые **обоими** компиляторами. Исходные наблюдения,
метки и `datasets/{gcc,clang}` не менялись.

```bat
python bd.py quality
python bd.py test-stage3
```

Для накопления собственных диагностик PGR_Make добавлены команды
`capture`, `ingest`, `audit-real`, `export-real`, `snapshot-real`.
Они создают данные в `catalog/real_cases.jsonl`,
`observations/real/observations.jsonl` и `datasets/real/` только при
явном импорте пользователя. Новые реальные наблюдения **не входят** в
поставленный синтетический корпус и не выдумываются.

Полный процесс, требования безопасности, формат импорта и ограничения:
`docs/TRAINING_STAGE3_RU.md` и `docs/REAL_DATA_CONTRACT_RU.md`.

## Этап 4 (BD v2.2): токенизация, кодирование и контрольная оценка

Исходная структура `BD` и версия размещения 2 сохранены. Новые файлы
размещены только в существующих разделах `catalog/`, `datasets/`,
`reports/`, `manifests/`, `tools/`, `docs/`.

Для быстрой проверки готовых артефактов:

```bat
python bd.py test-stage4
python bd.py verify-stage4
```

Для **повторного полного выпуска** из проверенной базы Stage 3:

```bat
python bd.py stage4
```

Формируются словарь **только на Train**, 117 классов (116 ошибок + CLEAN),
разреженные векторы для GCC/Clang и Baseline Naive Bayes с метриками и
матрицами ошибок. Обучение собственной нейросети на C++ **не входит** в
этот этап; контрольный алгоритм не подменяет её.

Описание команд и ограничений: `docs/TRAINING_STAGE4_RU.md`.
Контракт для будущего C++ загрузчика: `docs/STAGE4_DATA_CONTRACT_RU.md`.
