# Контракт Stage 4 для будущего C++ PGR Neural DatasetLoader

**Версия схемы:** `pgr-features-v1`. Формат UTF-8, JSON Lines (по одному объекту в строке).

Пример `datasets/encoded/gcc/train.jsonl` (схематически):

```json
{"id":"p_...","pair_id":"...","input":{"indices":[0,17,22],"values":[1,2,4]},"target":{"class_id":13,"stage_id":2}}
```

`input.indices` строго возрастают, без дублей, от `0` до `V-1`, где
`V = len(catalog/training/vocabulary.json["terms"])`.
`input.values` содержит положительные целые значения от 1 до 8 и имеет
ровно ту же длину. Пустой вектор допустим только для будущих других
корпусов; поставленный корпус содержит категориальные признаки.

`target.class_id` — индекс в `catalog/training/labels.json["classes"]`.
`target.stage_id` — индекс в `.../labels.json["stages"]`.
`labels.json["class_to_stage"]` определяет допустимое сочетание
стадии и класса. **Ни `target`, ни `id`, ни `pair_id` нельзя подавать
в сеть как признаки.** Последние два поля нужны лишь для проверки качества
разделения данных; обучающие тензоры формируются только из `input`.

`catalog/training/vocabulary.json` содержит:

```json
{"schema":"pgr-features-v1","min_df":2,"max_features":12000,"train_documents":11044,"terms":["..."]}
```

Порядок `terms` определяет индекс. Установка Stage 4 должна загружать
готовый словарь, **не создавать его снова на валидации или инференсе**.

Алгоритм получения чисел описан в `tools/stage4_features.py`. При
переносе в C++ необходимо проверить соответствие нормализации, порядка
токенов и результатов кодирования на общих золотых примерах. Версия
схемы изменяется при несовместимой смене нормализации.

Планируемый C++ API, **ещё не включён в этот архив**:

```cpp
struct SparseFeatures {
    std::vector<std::uint32_t> indices;
    std::vector<std::uint8_t> values;
};

struct EncodedRecord {
    SparseFeatures input;
    std::uint32_t classId; // только для обучения/оценки
    std::uint32_t stageId; // только для обучения/оценки
};
```

Данные могут быть дополнительно представлены плотными mini-batch тензорами
для собственной нейросети. Размер пространства признаков сейчас небольшой;
разреженный формат остаётся первичным, чтобы не расходовать память зря.

`reports/training/stage4_nb_model.json` — только сохранённые статистики
**контрольного алгоритма Naive Bayes**, а не веса нейросети и не `.pgrnn`.
Он содержит SHA-256 словаря и списка классов, чтобы не применять модель к
другой нумерации признаков.

Все выходы кодирования контролируются `manifests/stage4_snapshot.json`.
При изменении обучающего корпуса повторите `python bd.py stage4`.
