# PGR Neural — Stage 4: числовое кодирование и контрольная модель

## Цель и границы

Этот этап превращает **поставленные проверенные** `datasets/verified/{gcc,clang}`
в числовые входы для собственного PGR Neural, не изменяя исходные проекты,
таксономию, наблюдения, пары исправлений, разбиения и Stage 3.

**Это подготовка данных и контрольный алгоритм Naive Bayes, а не обучение
нейросети.** Для нейросетевого движка на C++ необходим отдельный этап.

Требуется Python **3.10+**, используются исключительно стандартные библиотеки.
Компиляторы, Qt, интернет, PyTorch и scikit-learn не нужны. Скрипты не запускают
программы из `projects/`.

## Одна точка запуска

Работать из `PGR_Net/BD`:

```bat
python bd.py info
python bd.py check
python bd.py audit
python bd.py test-stage3
python bd.py test-stage4
python bd.py verify-stage4
```

Пересоздание всех результатов Stage 4 (детерминированно):

```bat
python bd.py stage4
```

Раздельные операции:

```bat
python bd.py prepare-stage4 --min-df 2 --max-features 12000
python bd.py evaluate-stage4
python bd.py verify-stage4
```

`evaluate-stage4` **откажется работать**, если входные данные или подготовленные
векторы изменились после последнего `prepare-stage4`. `verify-stage4`
проверяет SHA-256 для всех входов и результатов кодирования Stage 4.

## Структура кодирования

Разрешённые поля модели: `input.language`, `input.compiler`,
`input.build_system`, `input.command_phase`, `input.build_exit_code` (только
факт нулевого/ненулевого завершения), `input.diagnostic`,
`input.files` (тексты исходников). Из исходника берутся токены, а не имя
папки с проектом. Для защиты от искусственных маркеров нормализуются
пути, сгенерированные суффиксы идентификаторов, числа и шестнадцатеричные
константы. Длины диагностики и исходников ограничены, повторения насыщаются.

**Запрещены в признаках:** `id`, `pair_id`, `target`, `fault_code`, `split`,
`expected_stage`, `match`, исправляющий патч и метки других наблюдений.

Словарь создаётся строго по двум **train**-файлам GCC и Clang, с порогом
частоты документа `min_df=2`. Val/Test не влияют на состав или порядок
словаря. Неизвестные токены не добавляются по ходу обработки, а считаются
как OOV. Список `classes` зафиксирован из таксономии 116 неисправностей
плюс `CLEAN`. Пять стадий берутся из отдельного контракта.

Каждый вход сохраняется как **разреженный целочисленный вектор**,
с отсортированными индексами и значениями; не нужно загружать гигантскую
плотную матрицу в память.

## Контрольная модель и честная оценка

Входит простой Multinomial Naive Bayes (сглаживание Лапласа `alpha=1`).
Он обучается на суммарных `train` GCC + Clang, а на `val` и `test` только
предсказывает. Отдельно выдаются прогнозы двух задач:

- 117 классов неисправности / CLEAN;
- 5 стадий сборки / исполнения.

Для обеих задач вычисляются **accuracy, macro-F1, weighted-F1**,
поклассовые precision/recall/F1 и полная матрица ошибок. Дополнительно
выводится majority-baseline: предсказывать самый частый класс `CLEAN`.
Проверки даны отдельно по GCC, Clang и их объединению.

**Важно:** на поставленном синтетическом корпусе результаты могут быть
очень высокими, потому что шаблоны примеров структурно близки между
разбиениями. Разделение по `pair_id` исключает прямой перенос пары между
train/test, но **не устраняет перенос семейств шаблонов**. Поэтому
тестовые метрики Stage 4 **не предсказывают** работу на настоящих сборках,
в частности Windows/Qt6/MSYS2. Реальных импортов в этой поставке нет.

Дальнейший этап: отдельная тестовая выборка настоящих размеченных ошибок,
проверка сдвига распределения и собственный обучаемый C++ движок.

## Безопасность и воспроизводимость

- Ни один `project` не запускается инструментами Stage 4.
- Все пути относятся к корню `BD`; инструменты не делают сетевых запросов.
- Текущие исходные JSONL не перезаписываются.
- Генерация не зависит от случайных чисел, порядка обхода каталогов и часов.
- Выходы пишутся атомарно; `stage4_snapshot.json` публикуется последним.
- Изменения в проверенных исходных выборках будут замечены проверкой SHA-256.
- При изменении алгоритма токенизации или словаря нужно перевыпустить Stage 4.
- Тесты проверяют детерминированность, нераскрытие меток и непересечение пар.
