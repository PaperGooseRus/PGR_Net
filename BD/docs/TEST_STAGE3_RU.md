# Проверки этапа BD v2.1

Рабочая среда проверки: Linux, Python 3.13.5.
Qt SDK, обучение нейросети, Windows/CMake-компиляция всех 7424 проектов
на данном этапе не запускались: цель — качество и сохранность данных.

Проверки:

1. `python bd.py check` — совпадение SHA-256 файлов поставленного снимка.
2. `python bd.py test` — четыре теста структуры BD v2 и генерации 116 пар во временном каталоге.
3. `python bd.py audit` — каталог, источники, пары, отсутствие разрыва split.
4. `python bd.py test-stage3` — 11 тестов: consensus-выборки, исходные SHA-256,
   карантин, идемпотентный импорт, сбой на некорректной разметке, защита от
   попадания дубликатов в разные split, обнаружение типовых приватных строк,
   сухой прогон, шаблон из build log, снимок изменяемых пользовательских данных.
5. `python bd.py quality` — повторная генерация verified-выборок без
   редактирования исходных C/C++ проектов и их наблюдений.
6. `python bd.py audit-real` — на новой поставке показывает `empty`:
   это корректно, реальные журналы пользователь пока не предоставил.

Факты исходной проверки:

- 7424 проекта, 3712 пар, 116 дефектных семейств.
- 28 несовпадений исходных GCC-наблюдений и 0 у Clang.
- 3684 консенсусно подтверждённых пар.
- 7368 записей **на каждый** компилятор (train 5522, val 922, test 924).
- Исходные datasets/gcc и datasets/clang **не перезаписывались**.
- Тест новой базы не доказывает работоспособность на реальных непохожих проектах.

После загрузки пользовательских данных проверяй `audit-real` и
`snapshot-real --verify`. Распределение ошибок по классам и стадиям
сохранено в `reports/validation/quality_gate.json`.
