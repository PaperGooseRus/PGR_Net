# Четыре контрольных этапа внедрения в PGR Neural

| Этап | Что сделать | Проверяемый результат |
|---|---|---|
| 1. Корпус | Использовать поставленные `projects/` и `labels/` либо заново выполнить `generate.py` + `make_repairs.py` | `audit.py --root .`: число проектов, пар, классов, разбиение без утечек |
| 2. Эталонное поведение | Запустить `verify.py` отдельно для GCC и Clang на своей машине | `observations/{gcc,clang}_report.json`: ожидаемые и реальные стадии, ноль несоответствий |
| 3. Датасет | Запустить `prepare_training.py --root . --include-sources` | `training/`: отдельные train/val/test по компиляторам, мишени не в поле `input` |
| 4. Обучение и внешняя оценка | На CPU обучить свой классификатор, оценить class-wise recall, macro-F1, confusion matrix; отдельно проверить реальные проекты PGR_Make | Скрипт оценки на неизменённом test split + дополнительная проверка на проектах, не созданных генератором |

Разделяйте ответственность: генератор создаёт исходники, компилятор фиксирует факты, exporter делает модельные записи, обучение отвечает только за рекомендательное предсказание. Базовый PGR Rule Classifier продолжает работать независимо. Подключение нейросети к PGR Core не должно предоставлять ей право автоматически править файлы.
